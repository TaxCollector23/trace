---
title: OpenCode
description: Connect Trace to OpenCode so it can show the session and stop risky commands.
---

[OpenCode](https://github.com/sst/opencode) is an open-source terminal coding
agent. Trace connects to it two ways:

1. A **local MCP server** exposing Trace's read tools (recent runs, patch summary, rollback).
2. A **guard plugin** that checks every Bash command before it runs and stops commands Trace classifies as dangerous.

The plugin is the important half. MCP tools are advisory; the plugin fires on
every command and can stop it, the same way the Claude Code and Cursor
integrations do. Everything stays on `127.0.0.1`.

## Install

```bash
trc integrations install opencode
# or wire up every agent at once:
trc integrations install all
```

This writes the MCP server to `~/.trace/integrations/opencode/index.js`, the
guard plugin to `~/.config/opencode/plugin/trace.js`, and idempotently patches
your global OpenCode config at
`~/.config/opencode/opencode.json` (XDG-aware, honoring `XDG_CONFIG_HOME`),
backing it up first and preserving any config you already have. The entry it adds:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "trace": {
      "type": "local",
      "command": ["node", "/Users/you/.trace/integrations/opencode/index.js"],
      "enabled": true
    }
  }
}
```

OpenCode uses an `mcp` map whose entries are `{ type: "local", command: [ ... ],
enabled: true }`, which differs from the `mcpServers` map that Cursor and Windsurf
use, so the installer writes the OpenCode-native shape.

The installer also adds the plugin path to OpenCode's `plugins` list. This works
with current OpenCode V2 and the V1 compatibility contract. Restart OpenCode to
load both. The MCP server and plugin both run under Node, so install Node 18 or
newer.

## How the guard plugin decides

The plugin registers V2's `execute.before` hook and V1's
`tool.execute.before` hook. Before OpenCode runs a `bash` command, it asks the
local daemon's guard:

- A high-risk command (a recursive force-delete, a force-push, a piped shell
  installer, a raw disk write) makes the plugin throw, which cancels the command
  before it runs.
- Anything else runs normally.

The plugin fails closed for command checks: if the daemon is not running or the
request errors, the command is stopped rather than silently running unchecked.
Edit review happens after the edit and is shown in the dashboard.

## Verify

```bash
trc integrations status
```

OpenCode should read **connected** with "MCP tools + session guard plugin". The
installer starts the daemon; if you stopped it later, run `trc daemon start`.

## Tools exposed

- `trace_check_command`
- `trace_get_recent_runs`
- `trace_start_run`
- `trace_end_run`
- `trace_record_event`
- `trace_get_patch_summary`
- `trace_get_rollback_options`

If the daemon is not running, tool calls fail closed and OpenCode proceeds without
Trace. The integration never blocks your agent.
