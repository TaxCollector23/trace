The Codex integration uses Codex lifecycle hooks. Codex CLI, the Codex desktop
app, and the Codex IDE extension share `~/.codex/hooks.json`, so one Trace
install can observe sessions from all three surfaces.

## Install

```bash
trc integrations install codex
```

This writes `~/.trace/integrations/codex/codex-hook.js` and patches
`~/.codex/hooks.json`. Restart Codex. In a Codex session, run `/hooks`, review
the Trace hook, and trust it when Codex asks. Codex requires this review for
user-installed hooks.

```bash
trc integrations status
```

The adapter script remains available as a fallback for older Codex versions:

```bash
trc run "codex <prompt>"
```

## What shows up on the dashboard

Every Codex session with the hook trusted appears as a Trace run. It includes:

- Every Bash tool call, including the guard decision. A `block` decision denies
  the call before Codex executes it.
- Tool completion events and the session lifecycle on **Session Timeline**.
- The final Git diff and policy findings on **Patch Review** and **Risk Center**.
- The folder and agent identity on the current-run card.

Trace cannot block a file edit before it lands because Codex's file-edit hook is
not used as a pre-edit policy boundary yet; it records and reviews the result
after the tool call. If the Trace daemon is unavailable, the Codex Bash hook
denies the call and tells you to start Trace, rather than silently claiming the
command was checked.
