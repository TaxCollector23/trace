The dashboard is served by the local daemon and is **local-only**. It binds to
`127.0.0.1` (never `0.0.0.0`), prefers port `8757`, and falls back to the next
available port (`8758`, `8759`, and so on) if that is busy. There is no account
and no authentication, because it is reachable only from your machine.

Open it with:

```bash
trc dashboard
```

This starts the daemon if it is not already running, finds the active port, and
opens your browser. The daemon serves the built React app in release builds, so
no separate server is needed.

## It is read-only over the API

The dashboard reads from the same local API the CLI uses. Everything it shows is
already in the local database. It does not connect to any remote service, and the
static landing page and any optional mirror must not connect to the local daemon.
See [Security Model](/security-model).

## The local API

The daemon exposes a small HTTP API under `/api/*` on the same loopback port. A
few endpoints worth knowing:

| Endpoint | Purpose |
| --- | --- |
| `GET /api/health` | Liveness plus the product `version`. |
| `GET /api/state` | Daemon state, including `active_projects` and `version`. |
| `GET /api/github/ratify` | The same ratify computation as `trc ratify`. |
| `GET /api/benchmarks/redteam` | The red-team benchmark results. |

These are reachable only from your machine.

## Development mode

You can run the dashboard against a running daemon with Vite's dev server:

```bash
cd apps/web
npm install
npm run dev      # http://localhost:5173, proxies /api to the daemon
```

In production the daemon serves the built static files from `apps/web/dist`.
