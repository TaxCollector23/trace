title: Agent Runs
description: What a monitored run captures, and how attribution works.
---

A **run** is one monitored session. It starts when you launch something through
Trace and ends when that command exits. Everything Trace knows about an agent's
work is organized under runs.

```bash
trc run "claude fix the login bug"
```

## What a run captures

1. The current project and a new run record.
2. A **checkpoint** of the git state before the command starts.
3. The starting git commit and whether the working tree was dirty.
4. File creations, edits, and deletions, via a debounced file watcher.
5. Command output, streamed to your console and saved to logs under
   `<project>/.trace/runs/<run_id>/`.
6. Risky command decisions: allow, warn, require approval, or block.
7. Secrets detected in diffs, command output, or changed files, always redacted.
8. The final git diff, the **source of truth** for the patch review.
9. Optional configured project checks (build and test).
10. A deterministic diagnosis when something fails.

Each of these is stored as a timeline event, so you can reconstruct exactly what
happened and in what order. `trc replay <run_id>` walks the timeline back at its
original pace.

## Why the wrapper matters

Trace works best when agents are launched **through** the wrapper:

```bash
trc run <command>
```

This is how Trace attributes commands, output, and risks to a run, and how the
command guard gets a chance to classify a command before it runs. The file
watcher and git diff can still observe changes a tool makes outside the wrapper,
but full command guarding and run attribution require `trc run` or a supported
integration point (Claude Code hooks, or the MCP servers). See
[Limitations](/limitations) and [Integrations](/integrations/overview).

## Run statuses

| Status | Meaning |
| --- | --- |
| `running` | The command is still executing. |
| `completed` | Finished with exit code 0 and passing checks. |
| `failed` | Non-zero exit or a failing check. |
| `blocked` | The command was blocked, or you declined an approval prompt. |
| `rolled_back` | The run's changes were rolled back via a checkpoint. |

## Checks

If the project config sets `default_checks` (for example `["npm run build", "npm
test"]`), Trace runs them after the wrapped command completes and records
pass/fail results as timeline events and test results. Skip them for a single run
with `--no-checks`. See [Configuration](/configuration).

## Reviewing a run from the terminal

You do not have to open the dashboard to review a run.

```bash
trc runs                 # recent runs across projects
trc show <run_id>        # summary + full timeline
trc patch <run_id>       # files added / modified / deleted
trc risks <run_id>       # guarded commands + redacted secret warnings
trc costs <run_id>       # token usage and estimated cost
trc replay <run_id>      # replay the timeline at its real pace
```

The dashboard shows the same data with a richer layout. See
[Local Dashboard](/local-dashboard).
