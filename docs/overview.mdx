Trace is a local-first control layer for autonomous coding agents. Those agents
now have a shell — they edit files, run commands, and rewrite git history in
seconds. Trace gives every session a complete record — commands, file changes,
risks, costs, checks, and rollback points — and stops the destructive command
before it runs, so you can review an agent's work the way you'd review a
coworker's pull request.

It is a black box recorder, a safety layer, a cost tracker, and a patch-review
command center that works the same regardless of which agent produced the run.

Trace tells you:

- **what changed** — files created, modified, or deleted
- **what ran** — the commands executed during a session
- **what looked risky** — blocked/warned commands and protected files
- **what may have leaked** — secrets detected in diffs, output, or files
- **what it cost** — API/model usage when it is available
- **what broke** — build/test results and a deterministic failure diagnosis
- **how to undo it** — Git-based checkpoints and rollback

## What Trace is not

- It is **not** a chatbot or an AI coding assistant.
- It does **not** replace your coding agent — it wraps whichever one you use.
- It does **not** send your project data anywhere. Everything stays on your
  machine in `~/.trace` and your project's `.trace/` folder.

Trace *wraps, observes, records, guards, and reviews* the agents you already
use.

## How it works

You launch an agent or command through the wrapper:

```bash
trc run "claude fix the login bug"
```

Trace creates a checkpoint, captures the starting Git state, watches the
project for file changes, records command output, scans for secrets and risky
commands, captures the final Git diff, optionally runs your configured checks,
and stores everything in a local SQLite database. You review it all in a local
dashboard at `http://127.0.0.1:<port>`.

<Note>
Trace observes terminal-based agents most directly. For GUI-based tools it
can still watch file changes and Git diffs, but it cannot guard the tool's
internal actions. See [Limitations](/limitations).
</Note>
