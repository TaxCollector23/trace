---
title: Secret Detection
description: Local, rule-based secret scanning that never stores raw secrets.
---

Trace scans for secrets locally with a rule-based scanner. It is the same engine
everywhere: the live run path, `trc check`, and the policy engine's
`secret-in-diff` rule all call into it, so a provider caught in one place is
caught in all of them. No network call, no API key.

## What it scans

- changed files during a run
- the git diff
- command output
- environment-related and protected files

## What it detects

Each pattern is anchored on the provider's distinctive prefix or shape, which
keeps false positives low.

| Type | Shape |
| --- | --- |
| `anthropic_api_key` | `sk-ant-...` |
| `openai_api_key` | `sk-...` / `sk-proj-...` |
| `github_token` | `ghp_` / `gho_` / `ghu_` / `ghs_` / `ghr_...` |
| `gitlab_token` | `glpat-...` |
| `aws_access_key` | `AKIA` + 16 chars |
| `aws_secret_key` | anchored on a nearby `aws...secret...key` label |
| `google_api_key` | `AIza...` |
| `groq_api_key` | `gsk_...` |
| `stripe_key` | `sk_live_` / `rk_test_...` |
| `slack_token` | `xoxb-` / `xoxp-...` |
| `sendgrid_key` | `SG.<part>.<part>` |
| `npm_token` | `npm_...` |
| `twilio_account_sid` | `AC` + 32 hex |
| `private_ssh_key` | `-----BEGIN ... PRIVATE KEY-----` |
| `jwt` | `eyJ<header>.<payload>.<signature>` |
| `database_url` | `postgres://`, `mysql://`, `mongodb://`, `mongodb+srv://...` |
| `generic_bearer_token` | `Bearer <20+ char token>` |

The AWS secret access key has no distinctive prefix, so it is anchored on a
nearby `aws...secret...access...key` label rather than flagging any random
40-character base64 string. The rule-pack system can add more patterns as data
without a new binary; see [Rule Packs](/rule-packs).

## Redaction

Trace **never stores raw secrets**. Every detected value is redacted to a short
prefix plus `...redacted` before it is stored or displayed:

```text
sk-ant-...redacted
ghp_...redacted
AKIA...redacted
```

The number of leading characters kept is tuned per type so the redaction is
enough to recognize a key without reconstructing it. This is a core safety
invariant of the codebase: the persisted value can never contain the full secret
body, and it is covered by tests that assemble the test inputs from fragments so
no contiguous secret literal exists even in the test source.

Each finding stores the secret type, file path (when applicable), the redacted
value, the action taken, the run id, and a timestamp. View them in the **Risk
Center** or with `trc risks <run_id>`.

## Protected files

Files listed in `protected_files` in your project config (for example `.env`,
`.env.local`, `id_rsa`, `secrets.json`) raise a warning when they are changed
during a run, even if no secret pattern matches their contents. Filenames that
look environment-like on their own (`.env`, `.env.*`, `id_rsa`, `secrets.json`,
`*.pem`) are recognized as sensitive regardless of the config. See
[Configuration](/configuration).

## A note on placeholders

Detection is by shape, so a long placeholder is sometimes indistinguishable from
a real token. A short, clearly templated value like `Bearer <your-token-here>`
stays below the length threshold and is not flagged, but a long placeholder such
as `Bearer your-token-here-example` is conservatively flagged. Trace prefers a
false positive you can dismiss over a real key that slips through.
